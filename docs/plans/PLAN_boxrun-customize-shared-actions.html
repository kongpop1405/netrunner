1Goal

สองคำขอจาก user แยกกันแต่ทำพร้อมกัน:

  • Boxrun customize เพิ่ม — เลือก boost ที่จะซื้อ (Magnet / Speed+17% / Double Coins / None) แทนที่ fix ไว้ที่ Magnet ตาม boxrun_toggle.json เดิม, และวิ่งได้อิสระทุก episode (ของเดิมก็ episode-agnostic อยู่แล้ว — bug คือ boost ผูกติดคนละไฟล์ต่อ ep3/ep5/ep6/toggle)
  • Shared function module — ดึง logic ที่ซ้ำกันในทุกบอท (Fast Start spam-tap, Cookie Relay tap, popup-probe close) ออกมาเป็น Python helper กลาง ให้ coinrun/giftdraw/sendlife/addfriend เรียกใช้ได้ ไม่ใช่ผูกกับ boxrun เท่านั้น

3Design — boost เลือกได้ (patch-based, ไม่แตะ engine)

ต่อยอด pattern เดิมของ run_toggle.py (deep-copy states → mutate → hand ให้ Runner) — ไม่แก้ src/config.py / src/fsm.py เลย เพราะ config loader ยังมองเห็น JSON เดิมเป๊ะ ความเสี่ยง regression = 0 ต่อ config อื่นที่ไม่ผ่าน toggle.

boxrun_toggle.json (base skeleton, Magnet placeholder) → --boost {magnet|speed|doublecoins|none} → _apply_boost(states, choice) แทนที่: - probe_magnet.detect → banner template ของ choice ที่เลือก - buy_magnet.on_match tap coords → coords ของ choice - start_run.detect → banner template เดียวกัน choice == "none" → redirect await_shop/boost_shop.on_match ตรงไป check_heart (ใช้ path เดียวกับตอน --magnet n ปัจจุบัน)

เปลี่ยน flag เดิม: --magnet y/n → --boost magnet|speed|doublecoins|none (breaking แต่ scope เล็ก, เป็น internal CLI ไม่มี user อื่นพึ่ง). boxrun_toggle.bat ถามคำถามใหม่แทนคำถาม Magnet y/n เดิม.

Templates ที่ต้องมีครบ 3 ชุด ใน templates/cookierun/: magneticaura_banner.png, speedbase17_banner.png, doublecoins_banner.png — ทั้ง 3 มีอยู่แล้วจาก config เดิม ไม่ต้อง crop ใหม่.

4Design — shared action types (engine-level)

เป้าหมายที่ user ระบุ: แก้บอทตัวเดียว บอทอื่นได้รับการแก้ด้วย. Helper ที่ generate dict ให้ launcher ไม่ตอบโจทย์นี้ — config 13 ไฟล์ hardcode action list เต็มอยู่บนดิสก์ แก้ helper ไม่ retroactive. ทางที่ propagate จริงคือย้าย behavior เข้า Actor แล้วให้ config อ้างด้วยชื่อ action.

ทำไมจุดนี้ใช่: Actor.run() ใน src/act.py เป็น dispatch จุดเดียวของทุก action, _ACTION_TYPES ใน src/config.py เป็น whitelist จุดเดียว. เพิ่ม type = แตะ 2 ไฟล์ แล้วทุก config ที่เรียก type นั้นได้ behavior ใหม่ทันที ไม่ต้องไล่แก้ JSON. Pattern เดิมที่รีโปเคยใช้ตอนเพิ่ม slide (RUN.md: "actuator มีแล้ว ขาดแค่ validator whitelist").

แก้ "กดบ้างไม่กดบ้าง" ตรงไหน

อ่าน act.py แล้วเจอ 2 กลไกที่ทำให้ tap หายเงียบ ๆ:

  • Blind tap ไม่เช็คจอ — tap_xy ยิง input tap ทันทีโดยไม่ verify ว่าปุ่มอยู่บนจอจริง. จอกำลังเฟด / ปุ่มยังไม่ render = tap ตกน้ำ FSM ไม่รู้ตัว. นี่คือ pattern "กดบ้างไม่กดบ้าง" ที่น่าจะเป็นสาเหตุหลัก
  • Jitter clip 8px — _jitter() Gaussian σ=3 clip ±8px. ปุ่มเล็ก/ขอบบาง มีโอกาสหลุดขอบ

ทางแก้ที่ action type ใหม่เปิดให้ทำได้: ใส่ retry loop + optional template-verify ไว้ใน executor ตัวเดียว — เช่น relay_tap ยิงแล้วเช็คว่าจอเปลี่ยนไหม ไม่เปลี่ยนยิงซ้ำได้ N ครั้ง. Tuning constant พวกนี้อยู่ใน act.py เป็น class attribute เหมือน slide_hold_ms/double_jump_chance ที่มีอยู่แล้ว — แก้ค่าเดียว ทุกบอทที่ใช้ action นั้นได้ทันที.

แก้บั๊ก "relay กดไม่ติด" ใน design ใหม่: 1. แก้ Actor.relay_retries = 2 ใน src/act.py (1 บรรทัด) 2. ทุก config ที่มี {"type": "relay_tap"} ได้ fix ทันที — ไม่ต้องแตะ JSON, ไม่ต้อง regen, ไม่ต้อง sync เทียบกับของเดิม: แก้ tap coord ใน boxrun_toggle.json → ep3, ep5, ep6, ep6v2, ep6box, norelay_noquit, coinrun ยังพังอยู่ → ต้องไล่แก้ 13 ไฟล์มือ

Migration (one-time, ทำเป็น script)

เขียน tools/migrate_action_types.py เดินทุก config/*/*.json แล้วแทน pattern ที่รู้จักด้วย action ใหม่ — เช่น run ของ tap_xy(985,515)+wait ที่ซ้ำติดกัน 12 รอบ → faststart_tap ตัวเดียว. รันครั้งเดียว, git diff review ทีละไฟล์, แล้ว config สะอาดขึ้นเยอะ (check_heart จาก ~140 บรรทัดเหลือ ~15).

สำคัญ Backward-compatible: tap_xy เดิมไม่ถูกลบออกจาก whitelist — config ที่ยังไม่ migrate รันได้ปกติ. Migration เป็น opt-in ต่อไฟล์ ถ้าไฟล์ไหน live-verified แล้วไม่อยากเสี่ยงก็ข้ามได้.

5Build steps

เรียงให้ทดสอบได้ทีละขั้น — จบขั้น A ก่อนค่อยขึ้น B ได้ (A กับ B ไม่ผูกกัน)

A. Shared action types

  1. เพิ่ม executor ใน src/act.py: relay_tap, faststart_tap, close_popup + class-attribute tunables (retry count, spam count, gap) วางข้าง slide_hold_ms ตาม pattern เดิม
  2. เพิ่ม 3 type เข้า _ACTION_TYPES + _REQUIRED_FIELDS ใน src/config.py (tap_xy คงไว้ ไม่ลบ)
  3. Unit test: action ใหม่ยิง device.shell ด้วย coord/จำนวนครั้งตรงกับ action list เดิมที่มันแทน
  4. เขียน tools/migrate_action_types.py — แทน pattern ที่รู้จักในทุก config, dry-run mode ก่อน (พิมพ์ diff ไม่เขียนไฟล์)
  5. รัน migration บน boxrun_toggle.json ก่อนไฟล์เดียว → dry-run FSM → live capped test → ค่อยขยายไฟล์อื่น

B. Boost choice

  1. เพิ่ม _BOOST_PROFILES dict ใน run_toggle.py: magnet/speed/doublecoins → (banner_template, buy_cell_xy, multi_toggle_xy); เขียน _apply_boost(states, choice) แทน _disable_magnet
  2. เปลี่ยน --magnet y/n → --boost {magnet,speed,doublecoins,none} ใน argparse; อัพเดต help text
  3. แก้ boxrun_toggle.bat: คำถาม "Buy Magnetic Aura boost? (y/n)" → "Which boost? (magnet/speed/doublecoins/none) [magnet]" — validate input, reject ค่าอื่นพร้อม re-prompt
  4. Dry-run 4 boost choice × --max-cycles 6 -v validate ไม่พัง goto target
  5. Live capped test boost ที่ไม่ใช่ magnet (speed) ยืนยัน buy chain จริงบนจอ

C. Docs

  1. RUN.md: section "Box Farm — Toggle" ตาม flag ใหม่ + section ใหม่อธิบาย shared action types (แก้ตรงไหนกระทบอะไร)

7Out of scope (ระบุชัดกัน scope creep)

  • ไม่ลบ tap_xy / action type เดิม — backward-compatible เสมอ, config ที่ยังไม่ migrate รันได้ปกติ
  • ไม่ทำ config-level import/fragment reference ("$ref" ใน JSON) — action type ตอบโจทย์ propagation แล้วโดยไม่ต้องแก้ loader
  • ไม่รวม boxrun_speed/ep5/ep6/norelay_noquit.bat เข้า toggle เดียว (คำถามที่ 1 ข้อ 2 ไม่ได้เลือก) — ยังแยกไฟล์ตามเดิม
  • ไม่ migrate ทั้ง 13 config รวดเดียว — ทีละไฟล์ + verify, ไฟล์ที่ live-verified แล้วข้ามได้ถ้าไม่อยากเสี่ยง
