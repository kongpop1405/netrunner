ห้ามซื้อหัวใจ
กฏเกมที่ทำให้ทุกอย่างพลิก: กด Multi-Buy ครั้งเดียว → เกมจะสุ่มบูสต์ให้เองเรื่อย ๆ (มี Stop + animation) จนได้บูสต์ที่ติ๊กถูก = Double Coins แล้วเกมหยุดเอง. บอทมีหน้าที่แค่ รอ ไม่ใช่วน buy ซ้ำ และห้ามแตะอะไรระหว่าง roll (แตะ = ไปโดน Stop = ตัดการสุ่มกลางคัน).

Bอาการ & สาเหตุ

#1 ซื้อบูสต์ซ้ำแม้ได้ Double Coins แล้ว

picker รอแค่ 3500ms แล้วไป check_boost_result → start_run. แต่เกมยังสุ่มเองไม่จบ → banner ยังไม่ใช่ Double Coins → start_run on_absent → boost_shop → เปิด picker กด Multi-Buy รอบใหม่ = buy ซ้ำทั้งที่เกมกำลังสุ่มให้อยู่แล้ว.

#2 กด Stop กลางคัน multi-buy

เพราะ #1 บอทกลับเข้ามากด/แตะ ระหว่าง roll animation ยังเล่นอยู่ → tap ไปโดนปุ่ม Stop → ตัดการสุ่มอัตโนมัติของเกมก่อนได้ Double Coins.

#3 หัวใจหมดแล้วยังพยายาม Play

ไม่มี state ไหนเช็คหัวใจเลย. หัวใจ = 0 → กด Play ไม่ได้/เด้ง dialog → loop รวน. ต้องรอจนหัวใจ ≥ 1 ค่อยวิ่ง. RULE ห้ามซื้อหัวใจด้วย gem เด็ดขาด · หัวใจ 1 ดวง = วิ่งได้.

FFlow ใหม่ (แก้แล้ว)

boost_shop → tap gift box → tap Multi → picker
  picker: tap Multi-Buy ครั้งเดียว
            → goto wait_roll            (state ใหม่: เฝ้า roll)
  wait_roll: detect = multibuy_marker / stop (roll กำลังเล่น)
            on_match  → ไม่แตะอะไร, wait, self-loop  (รอเกมสุ่มเอง)
            on_absent → roll จบแล้ว → goto start_run
  start_run: detect = doublecoins_banner
            on_match  → goto check_heart       (ได้ Double Coins)
            on_absent → goto check_heart       (roll จบแต่ไม่ใช่ DC → play ด้วยของที่ได้; ไม่ buy ซ้ำ)
  check_heart (state ใหม่): detect = heart_empty
            on_match  → หัวใจ=0 → wait, self-loop      (รอหัวใจ เติมเอง; ห้าม gem)
            on_absent → หัวใจ≥1 → tap Play → goto running

หัวใจของการแก้: ตัด loop start_run → boost_shop ที่ re-roll ทิ้ง (เกม roll เอง ไม่ใช่บอท) และ เพิ่ม wait_roll ให้บอทนิ่งจนเกมสุ่มจบ (แก้ทั้ง #1 buy ซ้ำ + #2 กด Stop ในทีเดียว). check_heart = #3.

Sขั้นตอนแก้ (config-only)

1. picker — เปลี่ยนปลายทางหลัง tap Multi-Buy จาก fixed wait 3500 → check_boost_result เป็น goto wait_roll (ลด wait ตายตัวลง, ให้ wait_roll คุมเวลาแทน).
2. เพิ่ม state wait_roll — detect multibuy_marker.png (ปุ่ม/animation ตอน roll). on_match = wait + self-loop (ไม่มี tap). on_absent = goto start_run. timeout_ms เผื่อ roll ยาว (~30–40s หลายรอบ).
3. start_run — เปลี่ยน on_absent จาก goto boost_shop (re-roll) เป็น goto check_heart. on_match ก็ไป check_heart (แทนที่จะ tap Play ตรง ๆ). ลบ path re-buy ทิ้ง.
4. เพิ่ม state check_heart — detect heart_empty.png (แถวหัวใจสีเทา/ว่าง มุมขวาบน). on_match = wait + self-loop (รอหัวใจ; ไม่ทำอะไร). on_absent = tap Play (1365,931) → wait 6000 → goto running.
5. จุด Play อื่น (force_play, play_home) — เดินผ่าน check_heart ก่อน tap Play ด้วย เพื่อกันวิ่งตอนหัวใจหมดทุกทาง.

TTemplate PNG ที่ต้องแคปเพิ่ม

heart_empty.png — ต้องแคปตอนหัวใจหมดจริง (มุมขวาบน แถวหัวใจ ~x 1300–1490, y 40–70 เป็นรูปหัวใจโครงเทา/ว่าง). ครอปให้แคบ เฉพาะหัวใจดวงแรกที่ว่าง. ยังไม่มีในโฟลเดอร์ — ต้องได้ก่อนถึงจะเทสต์ #3 ได้.
multibuy_marker.png — มีแล้ว ✓ ใช้เป็น detect ของ wait_roll ได้ทันที (ถ้า marker นี้ยังอยู่บนจอ = roll ยังไม่จบ). ถ้าพบว่าปุ่ม Stop ต่างจากนี้ อาจแคป stop_marker.png เสริม.

Rความเสี่ยง / ต้องยืนยัน

• wait_roll detect: multibuy_marker อยู่บนจอตลอดช่วง roll จริงไหม? ถ้าปุ่มเปลี่ยนเป็น "Stop" ระหว่าง roll อาจต้อง detect ปุ่ม Stop แทน. → เทสต์ --dry-run ดู log ก่อน.
• heart_empty false-negative: หัวใจ "1 ดวง" ต้องไม่ match template (เพราะ 1 ดวง = วิ่งได้). ครอปเฉพาะ state ว่างสุด (0 ดวง) ให้ชัด.
• timeout_ms ของ wait_roll: roll หลายรอบกินเวลานาน — ตั้งสั้นไปจะ bail กลางคัน. เริ่มที่ ~40000ms แล้วปรับ.
