Gเป้าหมาย

Engine กลาง auto-farm บน LDPlayer. วน loop: capture จอ (ADB screencap) → perceive รู้ state (OpenCV template match / OCR) → act ยิง tap/swipe (ADB input) ตาม FSM config. เกม-agnostic — เปลี่ยนเกม = เปลี่ยนแค่ config JSON + template PNG. RL ยังไม่ทำ.

Aสถาปัตยกรรม — 3 layer

1 · CAPTURE — adb exec-out screencap -p → PNG bytes → numpy/BGR. ห่อ device id, retry, timing.
2 · PERCEIVE — cv2.matchTemplate + optional OCR (tesseract). คืน state name + matched region.
3 · ACT — adb shell input tap/swipe. รับ region/coord จาก config, jitter+delay กัน pattern.
FSM RUNNER — อ่าน config JSON: state = {detect, on_match, next}. วนจน stop/error.

CConfig schema (FSM)

{
  "device": "emulator-5554",
  "poll_ms": 800,
  "match_threshold": 0.85,
  "start_state": "home",
  "states": {
    "home": {
      "detect": "home_marker.png",
      "on_match":  [{"type":"tap_template","template":"enter_stage.png"}],
      "on_absent": {"goto":"unknown"}
    },
    "battle": {
      "detect": "battle_marker.png",
      "on_match": [{"type":"wait","ms":3000}],
      "timeout_ms": 120000
    },
    "victory": {
      "detect": "victory_marker.png",
      "on_match": [{"type":"tap_template","template":"confirm.png"},
                   {"type":"goto","state":"home"}]
    }
  }
}

Action types: tap_template · tap_xy · swipe · wait · goto · stop. เพิ่ม type = เพิ่ม handler ใน act.py.

Bลำดับ build

  1. 01  scaffold: requirements, folder, README
  2. 02  device.py + capture.py — ต่อ ADB, screencap จริง → เทสต์ tools/snap.py
  3. 03  perceive.py — matchTemplate คืน (found, score, x, y)
  4. 04  act.py — tap/swipe/wait + jitter
  5. 05  config.py + fsm.py — โหลด JSON, วน loop, dispatch action
  6. 06  main.py + example_game.json — end-to-end (dry-run ได้แม้ไม่มี template)
