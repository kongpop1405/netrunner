Gเป้าหมาย

Engine กลาง auto-farm บน LDPlayer. วน loop: capture หน้าจอ (ADB screencap) → perceive รู้ว่าอยู่ state ไหน (OpenCV template match / OCR) → act ยิง tap/swipe (ADB input) ตามกฎที่กำหนดใน FSM config. เกม-agnostic — เปลี่ยนเกม = เปลี่ยนแค่ config JSON + template PNG ไม่แตะ engine. RL ยังไม่ทำ (interface เผื่อไว้เฉย ๆ).

Aสถาปัตยกรรม — 3 layer

1. Capture — adb exec-out screencap -p → PNG bytes → numpy/BGR. ห่อ device id, retry, timing.
2. Perceive — template match (cv2.matchTemplate) + optional OCR (tesseract). คืน state name + matched region.
3. Act — adb shell input tap/swipe. รับ region/coord จาก config, jitter+delay กัน pattern.
FSM runner — อ่าน config JSON: แต่ละ state = {detect: template, on_match: action, next: state}. loop จนเจอ stop/error.

CConfig schema (FSM)

{
  "device": "emulator-5554",
  "poll_ms": 800,
  "match_threshold": 0.85,
  "start_state": "home",
  "states": {
    "home": {
      "detect": "home_marker.png",
      "on_match":  [{"type":"tap_template","template":"enter_stage.png"}],
      "on_absent": {"goto":"unknown"}
    },
    "battle": {
      "detect": "battle_marker.png",
      "on_match": [{"type":"wait","ms":3000}],
      "timeout_ms": 120000
    },
    "victory": {
      "detect": "victory_marker.png",
      "on_match": [{"type":"tap_template","template":"confirm.png"},{"type":"goto","state":"home"}]
    }
  }
}

Action types: tap_template, tap_xy, swipe, wait, goto, stop. เพิ่ม type = เพิ่ม handler ใน act.py.

Bลำดับ build

  1. 1. scaffold: requirements, folder, README
  2. 2. device.py + capture.py — ต่อ ADB, screencap ได้จริง → tools/snap.py เทสต์
  3. 3. perceive.py — matchTemplate คืน (found, score, x, y)
  4. 4. act.py — tap/swipe/wait + jitter
  5. 5. config.py + fsm.py — โหลด JSON, วน loop, dispatch action
  6. 6. main.py + example_game.json — ต่อครบ end-to-end (dry-run ได้แม้ไม่มี template)
