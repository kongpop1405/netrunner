FFix — retry loop ที่ terminate ด้วย "เหรียญหมด" (ทางเลือก C)

ทำไมไม่นับรอบ (retry counter): FSM engine ไม่มี state variable — จะนับรอบต้อง chain state (retry_1 → retry_2 → …) = โค้ดบวม. ใช้ nocoins_marker เป็น ตัวจบ loop ตามธรรมชาติ แทน: เงินยังพอ = วนซื้อต่อ, เงินหมด = เกมเด้ง "Not enough Coins!" → Cancel → force_play. ไม่ต้องแตะ engine.

on_match (มี DC) ยังไป check_heart เหมือนเดิม — ไม่แตะ.

#2 state ใหม่ retry_buy — ด่านเช็คเงินก่อนซื้อรอบใหม่
"retry_buy": {
  detect: "nocoins_marker.png"
  on_match  → insufficient_coins   // เงินหมด → Cancel → force_play (ยอม Play ไม่มี DC)
  on_absent → buy_boost            // เงินพอ → ซื้อใหม่ วนจนได้ DC
}

วางไว้ก่อน buy_boost เพื่อไม่ให้วนกดซื้อทั้งที่เงินหมด. insufficient_coins / force_play ของเดิมใช้ได้เลย ไม่ต้องแก้.

on_absent → wait_roll

on_absent → [wait 1200ms] → picker_2

จาก log: picker ไม่ match (popup ยังเปิดไม่ทันหลังกด Multi 1500ms) → หลุดไป wait_roll → marker ก็ไม่มี (ไม่ได้ roll สักหน่อย) → ไหลถึง Play. เพิ่ม picker_2 = re-check รอบสอง (pattern เดียวกับ await_shop/await_shop_2 ที่ใช้ได้ผลแล้ว). ยังไม่เจอรอบสอง → retry_buy (ไม่ใช่ Play).

!ความเสี่ยง & ตัวกัน

Livelock — ถ้า DC ไม่มีวันออก + nocoins ไม่เคยขึ้น → วน retry_buy ⟲ buy_boost ไม่จบ. กัน engine เตือนเองที่ 100 poll ติด (_STUCK_STATE_WARN_CYCLES → Discord alert). และ retry_buy มี timeout_ms → ไหลลง buy_boost. ยอมรับได้: nocoins คือ terminator จริงในเกม — เหรียญลดทุกรอบซื้อ.
เผาเหรียญเร็วขึ้น — เดิมได้บูสอื่นก็ Play (จบ), ตอนนี้ซื้อใหม่จนได้ DC. ตั้งใจ คือสิ่งที่ user ขอ. Cap เหรียญ = wallet เอง.
แตะโดน Stop ระหว่าง roll (บั๊กเก่าที่ plan ก่อนแก้ไปแล้ว) กัน retry_buy เข้าถึงได้จาก start_run เท่านั้น ซึ่งอยู่หลัง wait_roll ยืนยันว่า multibuy_marker หายแล้ว = roll จบแล้ว. ไม่มีทางไปแตะระหว่าง roll.
