03Architecture decision — ทำไมไปที่ engine ไม่ใช่ JSON

ทั้ง 4 feature ต้องการอย่างเดียวกัน: state ที่อยู่ข้าม cycle (timer, counter, per-run flag). JSON FSM ปัจจุบันไม่มี concept นี้เลย — ทุก state ตัดสินจาก frame เดียว + absent_streak ที่ engine ถือให้

Featureต้องมีJSON ทำได้มั้ย
wait 30–60s ระหว่างเกมrandom delay ต่อ 1 รอบเกม ไม่ได้ wait.ms เป็นค่าคงที่ ไม่ random
session reset 1.5–3 ชม.timer ข้าม cycle + force-stop + verify ไม่ได้ ไม่มี timer, ไม่มี action ที่ restart app
boost 11 ตัวเลือก template ตอน runtime ฝืนได้ ต้องมี 11 config หรือ patch dict แบบ run_toggle.py
captcha solverวน 6 cell → classify → tap หลายจุด ไม่ได้ find() คืน peak เดียว ไม่ใช่ทุก match
lives routine 25–35 นาทีtimer ข้าม cycle + trigger ที่ state ปลอดภัย ไม่ได้ ไม่มี timer; state chain ของ send มีแล้ว (sendlife.json) แค่เรียกไม่ได้
popup coverage 10 ตัวprobe state + template ใหม่ ได้ append probe state — engine ไม่ต้องแก้ (Phase 6 = งาน config+template ล้วน)

ทางข้อดีข้อเสียเลือก
A. Subclass Runner ต่อ feature ไม่แตะ engine, pattern เดียวกับ BoxQuitRunner ที่มีอยู่ เปิด _run_actions ทับซ้อนกันหลายชั้น — 3 feature = 3 subclass ที่ต้อง compose กัน (จะชนกันเอง) ไม่

Feature ทั้งหมดเป็น engine concern จริง (นาฬิกา, การ restart app, การ classify ภาพ) ไม่ใช่ game logic — วางที่ engine ทำให้ทุก config ได้ประโยชน์ฟรี ไม่ต้องแก้ 13 ไฟล์ JSON. commit 406f408 พิสูจน์ pattern นี้แล้ว — shared actions ใน Actor ลบ JSON ไป 2,286 บรรทัด โดย behavior จูนที่เดียวถึงทุก config. Wait-between-games + human pacing DONE — pytest 139 passed

Config field ใหม่ (optional ทุกตัว — config เดิมไม่ระบุ = behavior เดิมเป๊ะ): 

// config JSON — top level, ทุก field optional
{
  "inter_game_delay_s": [30, 60],   // random.uniform ก่อนเริ่มเกมใหม่
  "inter_game_state": "home",        // state ที่ถือว่า "จบ 1 รอบ" (default: start_state)
  "poll_ms": [500, 900],             // เดิมรับ int เดียว — เพิ่มรูปแบบ range = สุ่มต่อ cycle
}

// action ระดับ state — wait รับ range ได้ (backward-compat: int เดียว = เดิม)
{ "type": "wait", "ms": [800, 1400] }

Engine: เมื่อ เข้า inter_game_state (transition เข้า ไม่ใช่อยู่แล้ว) และไม่ใช่รอบแรก → sleep uniform(*inter_game_delay_s) ก่อนรัน on_match. Log ค่าที่สุ่มได้ทุกครั้ง เพื่อยืนยันว่าไม่ใช่ค่าคงที่

ต่างจาก cookierun-bot: อันนั้น hardcode random.uniform(30, 60) ใน 4 ที่ (bot.py:148/188/198/309) — แก้ที่เดียวไม่ครบ. อันนี้อยู่ใน config = แก้ที่เดียว, ต่อ config ได้ต่างกัน

Wait jitter + poll jitter — ฆ่า metronome

cookierun-bot ทุก action ตามด้วย uniform(0.8, 1.4)s — ไม่มี delay ค่าคงที่สักจุด. netrunner กลับกัน: wait ทั้ง 754 จุดใน config เป็น fixed ms + poll_ms คงที่ 600 → ช่วงเวลาระหว่าง tap ในลูป (โดยเฉพาะ in-run hop J→J→S→J) เป็นจังหวะคงที่ = ลายเซ็นบอท

  • wait.ms รับ [min,max] — Actor สุ่มต่อครั้ง. int เดียว = behavior เดิมเป๊ะ (backward-compat, ไม่ต้อง migrate 754 จุดทันที — ทยอยเปลี่ยนเฉพาะจุด hot)
  • poll_ms รับ [min,max] — สุ่มต่อ cycle → hop cadence ไม่คงที่โดยไม่ต้องแตะ config state ใด
  • ไม่แตะ pre-tap jitter เดิม (Gaussian + hesitate ใน act.py:49-66 ดีอยู่แล้ว — ดีกว่า cookierun-bot)
✅ ทำแล้ว (commit e88dcec + ab03a7f) — parse_range() ตัวเดียวใช้ทั้ง 3 knob (poll / inter-game / wait) · scalar = behavior เดิมเป๊ะ ทุก config ไม่ต้องแก้ · เจอเพิ่มระหว่าง implement:
  • Delay ต้องผูกกับ transition ไม่ใช่ check ทุก cycle — เขียนแบบเช็คต้นลูปก่อน (if state == inter_game_state) แล้วเห็นว่าจะ re-fire ทุก poll ที่ยังอยู่ home (home มี absent_retries รอ marker settle = หลาย poll ต่อ 1 lap) → ย้ายไปอยู่ใน block state != prev_state ซึ่งเป็นจุดเดียวที่รู้ว่า "เพิ่งเข้า"
  • Idle ต้องไม่ถูกคิดเป็น match_timeout — idle 45s ที่ home แล้ว state_entered_at ไม่ reset = lap ถัดไป trip match_timeout escape ทันที (ถ้า state นั้นมี budget < 45s). Fix: reset state_entered_at หลัง idle. Interaction ข้าม phase ที่ไม่ได้อยู่ในแพลนเดิม — มีเทสครอบ
  • ต้องข้ามการ delay ครั้งแรก — start_state = inter_game_state ทั่วไป → ถ้าไม่ข้าม จะ idle 30–60s ก่อนเกมแรกโดยไม่มีเหตุผล (นั่นคือเกม 1 เริ่ม ไม่ใช่เกม 0 จบ)
  • poll_ms เปลี่ยน type ไม่ได้ — 4 test file สร้าง Config(poll_ms=1) ตรง ๆ → เพิ่ม field poll_ms_range แยก + poll_delay_s() helper แทนแก้ type เดิม
  • Hop waits jitter ได้ 0 จุด — คาดว่าจะ jitter jump_2/3/4 แต่ state พวกนั้น ใช้ relay_tap/jump (shared actions) ไม่มี wait เลย — cadence in-run คุมด้วย poll_ms อย่างเดียว ซึ่ง jitter แล้ว. ที่ jitter จริง = 24 popup settle waits
Enable ที่ boxrun_toggle.json เท่านั้น (config ทดลอง): poll 600→[500,750] · idle 30–60s ที่ home · 24 wait → range. อีก 12 config ยัง fixed จนกว่าตัวนี้จะรันผ่าน
