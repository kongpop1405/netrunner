โจทย์: Cookie Run เด้ง popup กันบอทแบบสุ่ม — หัวข้อ "Surprise! Find the jumping card!" หรือ "...sliding card!". การ์ด 6 ใบ (grid 3×2) รูปตัวละครเดียวกัน ต่างแค่ ท่า — บางใบทำท่าตรงคำถาม (กระโดด/สไลด์) บางใบล้ม/นอน. ปิดไม่ได้ ต้องแตะเฉพาะการ์ดที่ทำท่าตรงคำถามให้ครบทุกใบ แล้วยืนยัน. ตอบผิด = เสี่ยงโดนแบนไอดี.
เป้า: ให้บอท auto-solve — ตรวจทีละช่อง แยกท่า "ถูก" จาก "ผิด" แล้วแตะครบทุกใบที่ถูก.

Wทำไม config ล้วนไม่พอ

1. perceive.find คืน peak เดียว (จุด match ดีสุดจุดเดียว) — เลือกได้ 1 ใบ ไม่ใช่ "ทุกใบที่ถูก".
2. ต้องแยก 2 ท่าที่หน้าตา ~90% เหมือนกัน (ยืน/กระโดด vs ล้ม/นอน) — ต้องเทียบ score สองแบบต่อช่อง แล้วตัดสิน ซึ่ง action เดิมไม่มี.
3. ต้องวน 6 ช่องพิกัดตายตัว ทำ per-cell classify + แตะเฉพาะที่ผ่าน — ไม่มี primitive นี้ใน act.py.
→ เพิ่ม action เดียว solve_captcha (crop 6 cell → เทียบ correct vs wrong → แตะที่ correct ชนะ → Confirm). Config ที่เหลือ = state chain ปกติ.

AAction solve_captcha (เฟส A)

{ "type": "solve_captcha",
  "cells": [ [cx,cy], ...6 จุด center ของแต่ละการ์ด ],   TODO วัดจริง
  "crop":  [w, h],                  ครึ่งกว้าง/สูง หน้าต่าง crop รอบ center
  "correct_tpl": "captcha_jump.png",   ท่าที่ถูก (กระโดด/สไลด์)
  "wrong_tpl":   "captcha_lie.png",    ท่าที่ผิด (ล้ม/นอน)
  "margin": 0.04,                   correct ต้องชนะ wrong เกินระยะนี้ ถึงจะแตะ
  "confirm_xy": [cx, cy] }          ปุ่มยืนยันหลังเลือกครบ  TODO
Algorithm: ต่อ 1 cell → crop region รอบ center → match correct_tpl ได้ score_c, match wrong_tpl ได้ score_w → ถ้า score_c > score_w + margin = ท่าถูก → เก็บไว้แตะ.
ถามคำ: "jumping" vs "sliding" ใช้ correct_tpl คนละไฟล์ — เลือกไฟล์ตามหัวข้อ (มี state แยก 2 ทางตาม marker หัวข้อ).
แตะ: ทุก cell ที่ผ่าน แตะทีละใบ (ผ่าน _jitter เดิม = human noise), เว้นจังหวะสุ่มสั้น ๆ ระหว่างแตะ. จบแล้วแตะ confirm_xy.
Safety: ถ้าไม่มี cell ไหนผ่านเลย (classify ไม่ชัด/template เพี้ยน) → ไม่แตะอะไร ไม่ Confirm → คืน sentinel ให้ FSM ไป state captcha_bail = beep + stop (ให้คนมาต่อ ดีกว่าตอบมั่วโดนแบน).

FFSM states (เฟส A skeleton)

ทุก probe state ในลูป (probe_congrats, probe_levelup, running ...)
   จะแทรก probe_captcha ก่อน — captcha เด้งทับได้ทุกจังหวะ

probe_captcha: detect = captcha_marker.png (แถบหัว "Surprise! Find the")
   on_match  → goto captcha_which
   on_absent → (probe ถัดไปตามเดิม)

captcha_which: detect = captcha_jump_title.png ("jumping card")
   on_match  → solve_captcha(correct=jump)  → goto captcha_recheck
   on_absent → goto captcha_slide      (ไม่ใช่ jump = ลอง slide)

captcha_slide: detect = captcha_slide_title.png ("sliding card")
   on_match  → solve_captcha(correct=slide) → goto captcha_recheck
   on_absent → goto captcha_bail       (หัวข้อแปลกใหม่ ไม่รู้จัก)

captcha_recheck: detect = captcha_marker.png
   on_match  → ยังอยู่ (ตอบไม่ผ่าน/ยังไม่ครบ) → goto captcha_bail
   on_absent → ผ่านแล้ว → goto running/home (กลับลูปฟาร์ม)

captcha_bail: beep(key) + stop   แจ้งคน มารับช่วง

หลักการ: ลองครั้งเดียว — solve → recheck. ยังอยู่ = ไป bail ทันที ไม่ retry มั่ว (ตอบผิดซ้ำ = สัญญาณบอทชัดขึ้น). Conservative เพราะ downside = แบนไอดี.

Bเฟส B — เก็บ template จริง (ตอน user เจอ captcha)

ยังทำเฟส B ตอนนี้ไม่ได้: user ยังไม่เคยเจอ captcha เอง → ไม่มี live snap @1920×1080. Screenshot ในแชท = จอคนอื่น สเกลต่างกัน (×1.17/×1.20) → crop template + วัดพิกัดจากมันไม่แม่น (matchTemplate ไวต่อ scale). ต้องรอ captcha โผล่บนจอ user แล้ว snap.
1. เจอ captcha → python tools/snap.py เก็บจอเต็ม (อย่าแตะจอ).
2. Crop: captcha_marker (แถบหัว), captcha_jump_title/captcha_slide_title (คำในหัวข้อ), captcha_jump/captcha_lie (ท่าถูก/ผิด จากช่องตัวอย่าง).
3. วัด 6 cell center + confirm_xy จาก snap จริง (grid 3×2). เสียบลง config.
4. Verify score: correct-pose ต้องชนะ wrong-pose ชัดในช่องที่ควรถูก, และกลับกันในช่องที่ควรผิด — ปรับ margin จนแยกขาด.
5. Dry-run: solve_captcha ต้อง log "จะแตะ cell 1,2,3,5,6 (ข้าม 4)" ตรงกับตาที่คนอ่านภาพ ก่อนปล่อยแตะจริง.
หมายเหตุ: ตัวละคร cookie สลับได้หลายแบบ (ในภาพเห็น 4+). ท่า "ล้ม/นอน" เป็น silhouette แนวนอนคล้ายกันข้ามตัวละคร → captcha_lie อาจ generalize ได้ ต้องเทสต์. ถ้าไม่ → เก็บ pose ต่อ cookie.

#ไฟล์ที่แตะ

src/act.py — เพิ่ม method solve_captcha + dispatch ใน run(). คืน sentinel __captcha_fail__ เมื่อ classify ไม่ผ่าน.
src/config.py — เพิ่ม "solve_captcha" ใน _ACTION_TYPES + required fields (cells, correct_tpl, wrong_tpl, confirm_xy).
src/fsm.py — รับ sentinel __captcha_fail__ → route ไป state bail (คล้าย _STOP).
config/cookierun.json — เพิ่ม captcha states + แทรก probe_captcha เข้า probe chain.
templates/cookierun/captcha_*.png — เฟส B (ยังไม่มี).
ทำเลยตอนนี้ (เฟส A): engine action + FSM sentinel + config skeleton (มี placeholder TODO ตรงพิกัด/template). บอทจะปลอดภัยทันที — เจอ captcha ก็ไม่วิ่งต่อมั่ว, ไป captcha_bail beep+stop. พอ auto-solve พร้อม (เฟส B) ค่อยเปิดใช้.
